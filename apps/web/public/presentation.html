Expenso — Personal Finance & Expense Tracker

High-Performance, Privacy-First Personal Finance Web Application

🎯 Project Core Concept

A modern, full-stack financial dashboard engineered to log transactions in under 5 seconds with zero data leakage, intelligent category keyword auto-detection, and real-time visual cashflow analytics.

FastAPI (Python) Modular Vanilla JS Clean Architecture SQLite / SQLAlchemy

Context & Motivation

Problem Statement & Existing Gaps

❌ Tedious Logging

Existing mobile & web apps require 5-6 clicks, multiple dropdowns, and slow transitions just to record a single cup of tea or coffee.

❌ Privacy & Ad Trackers

Commercial finance apps frequently read SMS inboxes, upload sensitive financial data to 3rd-party ad networks, and lack transparency.

❌ Bloated Frameworks

Heavy client-side bundles (10MB+ React/Angular SPAs) cause sluggish load times, high memory usage, and poor responsiveness on low-end devices.

💡 Our Core Engineering Principle

"Minimum Clicks → Maximum Information with Zero-Latency Logging"

Expenso removes all friction: centered hero action button, automatic category prediction from keywords, and keyboard-first navigation.

Solution Overview

Proposed Solution & Core USPs

⚡ Smart Category Auto-Detection

User simply types "Pizza 250" or "Uber cab" in the description — the app automatically identifies keywords and selects the category instantly without manual dropdown searching.

🔒 Isolated Income & Expense Engine

Dedicated logic guarantees that logging expenses never pollutes subsequent income entries (clean state reset, optional description, default UPI method).

📈 Real-Time Visual Intelligence

Live IST (Indian Standard Time) greeting, dynamic spending donut chart, monthly cashflow trend lines, and category budget progress caps.

⌨️ Power-User Keyboard Navigation

Ctrl+K for command bar, E for expense modal, I for income modal, / for ledger search, and Esc to dismiss modals.

Software Engineering

System Architecture & Monorepo Design

# Monorepo Clean Architecture
expenso/
├── apps/api/          # High-Speed FastAPI Backend

│   └── domain/      # Domain Modules

│       ├── analytics/
│       ├── budgets/
│       └── recurring/
├── apps/web/          # Modular Vanilla Client
│   └── public/
│       ├── css/     # Tokens, Base, Components
│       └── js/      # Services, Views, Modals
└── AGENTS.md         # < 500 LOC per file Rule

🏛️ Clean Architectural Standards

  • Strict Line Limit Rule: No file in the codebase exceeds 500 lines of code. Modular, readable, and highly maintainable.
  • Separation of Concerns: Routers handle HTTP, Schemas validate data, Models interact with ORM, Views render UI.
  • No Framework Bloat: Zero dependency client bundle loads in milliseconds and runs reliably on any browser without compile steps.
Data Layer

Database Schema & Relational Design

🗄️ Relational Entities (RDBMS)

  • Users: id, name, email, password_hash, currency, created_at
  • Transactions: id, user_id, amount, type, description, category_id, payment_method_id, date
  • Categories: id, user_id, name, type, icon, color, is_default
  • Payment Methods: id, user_id, name, type (UPI, Cash, Cards)
  • Budgets: id, user_id, category_id, amount, month, year
  • Recurring: id, user_id, name, amount, frequency, next_date

🛡️ Data Integrity & Constraints

  • Foreign Key Cascades: When a user or category is deleted, related records are cleaned automatically (ondelete="CASCADE").
  • Data Isolation: Every query strictly filters by user_id == current_user_id. No user can see another user's financial ledger.
  • ORM Efficiency: Uses SQLAlchemy joinedload for eager loading categories and payment methods in a single SQL query.
Backend Architecture

FastAPI Backend & Security Implementation

🔒 Security Implementation

  • Password Hashing: Passwords hashed with bcrypt (salt rounds) via Passlib. Plaintext is never stored.
  • Stateless JWT Auth: HS256 algorithm generates signed access tokens with configurable expiry (7 days).
  • Dependency Injection: Depends(get_current_user_id) guards all private endpoints.
  • SQL Injection Safe: Parameterized queries via SQLAlchemy ORM prevent SQL injection attacks.
# Auth Guard Dependency Example
def get_current_user_id(
  token: str = Depends(oauth2_scheme)
) -> int:
  try:
    payload = jwt.decode(token, SECRET, algorithms=["HS256"])
    return int(payload.get("sub"))
  except JWTError:
    raise HTTPException(status_code=401)

Feature Deep-Dive

Smart Transaction Engine & Auto-Detection

🧠 Keyword Recognition Engine

As the user types into Description, a live listener parses keywords against category taxonomies:

  • "Pizza", "Burger", "Chai" ➔ Auto-selects Food & Dining 🍔
  • "Uber", "Metro", "Petrol" ➔ Auto-selects Transport 🚕
  • "Amazon", "Blinkit", "Jeans" ➔ Auto-selects Shopping 🛒
  • "Electricity", "WiFi", "Recharge" ➔ Auto-selects Bills & Utilities 💡

🛡️ Streamlined UX Rules

  • Add Expense: Description is optional. If left blank, category name is automatically used as fallback.
  • Add Income: Description input is hidden for a cleaner layout. Only Amount, Category, and Date are needed.
  • Default Payment Mode: Automatically pre-selects UPI for modern fast payments.
